# 建立二次开发工作区的提案

## Why

**开发动机**　Codex、Claude Code 或下一次对话接手 OpenMausBot 二次开发时，需要从同一份仓库记录分清已确认的目标、实际进度和下一步。维护者要求每次开发先看方案，再决定是否实施。

变更编号为 `bootstrap-dev-workspace`，本次送审版本为 **R1**。本提案针对开发仓库。

## What Changes

**改动范围**

- 在已有根 `AGENTS.md` 增加简短的启动、确认和交接约定，保留上游规则和目录级覆盖。新增根 `CLAUDE.md`，内容仅为 `@AGENTS.md`。
- 在 `openspec/WORKSPACE.md` 维护二开目标、当前优先事项、影响多个变更的决定及其出处。变更索引使用 `openspec list`；具体任务继续使用各变更的 `tasks.md`。
- 在各活动变更的 `handoff.md` 记录负责人、分支、基线、方案版本与确认出处、最近一次验证、阻塞和下一步。这次提案附一条可供接手的真实初始记录。
- 用当前机器已有的 OpenSpec CLI 在仓库中完成最小配置，使用 `spec-driven` 工作流。首版通过文件和 CLI 协作；仓库内的助手入口不依赖某个人的全局设置。
- 用干净会话接手、修订失效、并行编辑冲突和归档四个场景验收。详细条件见增量规范。

## 涉及的能力

### 新增能力

- `developer-workspace`：开发智能体从共享事实恢复工作，并在维护者确认的范围内实施、验证和交接。

### 已有能力调整

无。

## 影响与验收

实施范围为根 `AGENTS.md`、新增根 `CLAUDE.md`、`openspec/WORKSPACE.md`、`openspec/config.yaml` 及本次变更的规范和记录。归档后形成 `openspec/specs/developer-workspace/spec.md`。应用源码、生产数据、账号权限、发布和 CI 均在本次范围之外。

**验收**：换一个没有旧聊天的智能体，仅凭仓库可以说出目标、当前版本、是否获准、下一步及证据。方案发生实质变化后，原确认失效。

**恢复**：本次实施仅涉及开发文档和配置。按实际差异撤回引导段落和新配置，保留已确认的提案及交接历史。维护者有同期修改时逐项合并。
