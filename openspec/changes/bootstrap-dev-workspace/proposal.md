# 二次开发工作区 · R2 提案

## Why

维护者希望不同智能体能接手 OpenMausBot 二次开发，同时控制重复读取的 token 开销。R1 接手时要求通读当前变更。R2 把日常查询、首次实施、最终审计需要的资料写清楚。[R1 提案原文](history/proposal-R1.md)供追溯。

## What Changes

- 变更编号 `bootstrap-dev-workspace`，当前版本 **R2**。根入口根据任务引导读取；已知变更的状态查询只需交接顶部，未知时先定位。历史授权和验证证据完整留存。
- 首次实施前核对提案原文、适用任务和规范、授权出处与现场差异。同一授权范围覆盖连续修改与验证。范围、权限或验收改变时先展示修订并取得确认。
- 更新现有工作区规则、OpenSpec 配置及本变更的规划和交接。保留两种客户端共用的入口。范围限于仓库内的开发流程与验证。

## 影响与验收

1. 无旧聊天的接手者只读短入口与摘要，即可报告版本、负责人、授权状态、最近验证、下一步和证据位置。
2. 准备写代码时能从摘要找到本版提案，核对任务、规范、授权与目标差异。待确认、撤回、出处不可核实或版本不符时暂停实施。已确认范围内可继续下一项任务。
3. 用同一分词器比较 R1 完整接手与 R2 状态查询、首次实施的实际文档输入。最终审计能取回 R1 原始提案、两版确认、测试证据和逐文件差异。只在维护者最终接受后正式归档。

**恢复方式**　若退回，仅修订有问题的规则并重新送审。如需恢复 R1，可按历史提案恢复原接手顺序，并同步根规则、总览、配置与规范；交接保留两版的决定和证据。
