# Spec: add-customer-portal（客户 Web 门户 + 管理后台）

> 每条都是一条可测的验收标准。写代码之前先读 specs，测的时候一条一条对。

## 1. 客户登录

- **WHEN** 客户打开客户 Web 并扫飞书码 **THEN** 控制面把扫码得到的 `open_id` 映射到 `tenant_id`，登录成功，只看到该租户的数据。
- **WHEN** 客户 A 登录后直接访问客户 B 的 Ticket 链接 **THEN** 服务端返回 403，页面显示“无权查看”，不是只在列表里藏起来。
- **WHEN** 同一租户的老板和运营各扫各的码登录 **THEN** 两人看到同一个租户的数据，但运营改不了预算上限和审批人名单（管理员才能改）。

## 2. 客户 Web 门户：只能看自己

- **WHEN** 客户打开 Bot 列表 **THEN** 只看到他自己的采购 / 跟单 / 巡检 Bot，看不到别的客户的 Bot。
- **WHEN** 客户打开消耗页 **THEN** token 消耗和业务消耗两本账分开显示，日 / 月汇总和 MVP2b 的双口径数字对得上。
- **WHEN** 客户打开定时任务页 **THEN** 巡检频率、日报时间、任务开 / 关状态和控制面当前配置一致。
- **WHEN** 客户在手机、iPad、电脑上打开同一条审批 **THEN** 三台设备看到的是同一个状态，不是一台已批准、另一台还待处理。

## 3. 客户能改的东西

- **WHEN** 客户把巡检从每天 2 次改成每天 1 次 **THEN** 下次巡检按新频率跑，审计里记“谁、什么时候、改了什么、改前改后”。
- **WHEN** 客户把预算上限改高 **THEN** 只有管理员角色能改成功，普通成员改了返回 403。
- **WHEN** 客户把某个 Bot 关掉 **THEN** 该 Bot 不再接新任务，正在跑的 Ticket 不受影响，审计里记一笔。
- **WHEN** 客户直接调接口改核心技能 **THEN** 服务端返回 403，MVP5 的哈希校验不通过，前端有没有按钮都不影响。

## 4. 双通道审批

- **WHEN** 有新的审批 **THEN** 飞书群里弹一张卡，客户 Web 待办里同时多一条，两边显示的是同一条审批记录。
- **WHEN** 用户在飞书上点了“允许” **THEN** 网页上那条立刻变“已处理”，显示“已由 XX 在飞书批准”，再点没用。
- **WHEN** 用户在网页上点了“拒绝” **THEN** 飞书那张卡立刻变“已处理”，显示“已由 XX 在网页拒绝”，再点没用。
- **WHEN** 飞书和网页同时点同一条审批 **THEN** 只有一个生效，审计里只记一笔，记清在哪边点的、谁点的、什么时候。
- **WHEN** 不是审批人的人在网页上点审批 **THEN** 返回 403，审批状态不变。

## 5. 管理后台

- **WHEN** 管理员登录管理后台 **THEN** 能看到所有客户列表、每个客户的 VM 状态（醒 / 睡、资源用量）、消耗、账单、审批和审计。
- **WHEN** 客户账号尝试登录管理后台 **THEN** 登录被拒绝，不能看到任何其他客户的数据。
- **WHEN** 管理员改核心技能哈希 **THEN** 必须走审批，改完审计里记一笔；不走审批直接改返回 403。
- **WHEN** 管理员给一个客户做销户 **THEN** 先导出该客户的数据，再彻底删除，有删除记录；导出只能导出该客户的，不能导出全部。

## 6. 租户隔离（直接调接口也要拦）

- **WHEN** 登录客户 A 的账号，直接调接口拿客户 B 的 Ticket、审批、消耗、记忆 **THEN** 全部返回 403。
- **WHEN** 客户导出自己的数据 **THEN** 导出文件里只有该客户的数据，没有别的客户的。

## 7. 验收与归档

- **WHEN** `openspec validate --all --strict --no-interactive` 运行 **THEN** 全部通过。
- **WHEN** `tasks.md` 全部勾完 **THEN** `handoff.md` 写清基线、复用盘点、批准和下一步，再归档推送。
