# customer-portal Specification

## ADDED Requirements

### Requirement: 客户通过飞书扫码登录并按服务端租户与角色隔离
系统 MUST 提供客户 Web 门户的飞书扫码登录流程（第一版不设密码登录），将扫码得到的 `open_id` 映射到 `tenant_id` 与租户内角色（`admin` 管理员 / `member` 普通成员）并签发短期控制面会话。同一租户多人各扫各的码登录后 MUST 看到同一租户数据，且普通成员 MUST NOT 修改预算上限与审批人名单（服务端返回 403）。

#### Scenario: 飞书扫码登录仅可见本租户数据
- **WHEN** 客户打开客户 Web 并完成飞书扫码登录
- **THEN** 控制面把扫码得到的 `open_id` 映射到 `tenant_id`，登录成功且仅返回该租户数据

#### Scenario: 跨租户直接访问返回 403
- **WHEN** 客户 A 登录后直接调用接口访问客户 B 的 Ticket、审批、消耗或记忆
- **THEN** 服务端返回 403，前端显示“无权查看”，不依赖前端隐藏

#### Scenario: 同租户管理员与普通成员权限隔离
- **WHEN** 同一租户的老板（管理员）和运营（普通成员）分别扫码登录，运营尝试修改预算上限或审批人名单
- **THEN** 两人看到同一租户数据，但运营的修改请求被服务端返回 403 拒绝

### Requirement: 客户 Web 门户 6 页审计与自助能力
系统 MUST 复用 OpenMausBot 设计系统提供响应式客户 Web 门户（手机、iPad、电脑均可打开，会话与审批状态保存在控制面），包含 6 个页面：Bot 列表、Ticket 与审批、消耗、定时任务、记忆与技能、设置。

#### Scenario: Bot 列表隔离与开关审计
- **WHEN** 客户打开 Bot 列表并关闭某个属于自己的 Bot
- **THEN** 仅看到自己的采购 / 跟单 / 巡检 Bot，关闭后该 Bot 不再接新任务（正在跑的 Ticket 不受影响），控制面审计记一笔（谁、什么时候、改前改后）

#### Scenario: 双口径消耗账本与预算上限
- **WHEN** 客户打开消耗页查看日 / 月汇总，管理员调高预算上限
- **THEN** token 消耗与业务消耗两本账分开显示并与 MVP2b 双口径数字一致；管理员修改成功并记审计，普通成员修改返回 403

#### Scenario: 定时任务与巡检配置修改
- **WHEN** 客户把巡检频率从每天 2 次改成每天 1 次或调整日报时间与任务开关
- **THEN** 配置写入控制面、下次巡检按新频率执行、页面显示“已生效 / 下次执行生效”，审计记录谁、什么时候、改了什么、改前改后

#### Scenario: 多端会话与审批状态一致
- **WHEN** 客户在手机、iPad、电脑上打开同一条审批
- **THEN** 三台设备从控制面读取并看到完全一致的审批状态

### Requirement: 客户不可修改核心技能与受保护规则
系统 MUST 在前端隐藏核心技能修改入口并在服务端强制拦截任何客户对采购、付款、数据删除三类核心技能的修改请求（返回 403 并沿用 MVP5 核心技能锁与哈希校验），且客户 MUST NOT 看到或修改 Vault 中的真实凭据。

#### Scenario: 客户直接调接口改核心技能被 403 拦截
- **WHEN** 客户绕过前端直接调接口修改核心技能
- **THEN** 服务端返回 403 并记录锁定拒绝审计，核心技能内容与哈希保持不变

### Requirement: 飞书与网页双通道原子审批
系统 MUST 将待处理审批同时推送到飞书卡片和客户 Web 待办（共享控制面同一条审批记录），并复用 MVP2b `server/approvals/store.ts` 的原子条件更新保证状态仅能从待处理变迁一次；一边操作后另一边 MUST 立即失效显示“已处理”，并发双通道点击 MUST 仅生效一次并记录来源通道与操作者，非指定审批人点击 MUST 返回 403。

#### Scenario: 飞书批准后网页同步失效
- **WHEN** 用户在飞书上点击“允许”
- **THEN** 网页待办立刻变“已处理”并显示“已由 XX 在飞书批准”，再点无效

#### Scenario: 网页拒绝后飞书卡片同步失效
- **WHEN** 用户在网页上点击“拒绝”
- **THEN** 飞书卡片状态立刻变“已处理”并显示“已由 XX 在网页拒绝”，再点无效

#### Scenario: 双通道并发点击仅生效一次
- **WHEN** 飞书和网页同时点击同一条审批
- **THEN** 仅有一个生效，另一侧返回幂等已处理，审计只记一笔有效决策并标明渠道、操作人与时间

#### Scenario: 非指定审批人网页点击被拒绝
- **WHEN** 不是指定审批人的人在网页上点击审批
- **THEN** 服务端返回 403，审批状态不变

### Requirement: 独立管理后台与高危操作受控审计
系统 MUST 提供独立于客户门户的管理后台（独立管理员账号体系、支持吊销管理员账号、客户账号登录管理后台 MUST 被拒绝），支持跨租户查看所有客户列表、VM 状态（醒 / 睡、资源用量）、消耗账单、审批与审计日志，支持租户开通与销户（先导出仅含该租户的数据再彻底删除并留删除记录），以及管理修改核心技能哈希 MUST 经过审批与二次确认（不走审批直接改返回 403）。

#### Scenario: 管理员跨租户查看与客户被拒
- **WHEN** 管理员登录管理后台，客户账号尝试登录管理后台
- **THEN** 管理员看到全部租户 VM 状态、消耗、审批与审计；客户账号登录或访问管理接口被拒绝（403）

#### Scenario: 管理员修改核心技能哈希必须走审批
- **WHEN** 管理员未走审批直接修改核心技能哈希 vs 经审批与二次确认后修改
- **THEN** 未走审批直接修改返回 403；走审批并二次确认后更新成功并写入审计日志

#### Scenario: 管理员执行租户销户先导出再删除
- **WHEN** 管理员对某客户执行销户
- **THEN** 先导出仅含该客户数据的导出包（不含其他租户），再彻底删除并生成不可变删除记录

### Requirement: 租户数据导出严格隔离
系统 MUST 在客户自助导出或管理员按租户导出时强制按 `tenant_id` 过滤，导出文件 MUST 仅包含目标租户的数据。

#### Scenario: 客户导出仅含本租户数据
- **WHEN** 客户导出自己的数据
- **THEN** 导出文件只包含该客户自己的数据，不包含任何其他租户的数据
