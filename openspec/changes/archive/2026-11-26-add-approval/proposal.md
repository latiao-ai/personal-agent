## 为什么改

- MVP2a 只做到了“每件副作用工作先变一张 Ticket”，但 Ticket 生成之后，Bot 还是不知道“能不能执行”。
- 没有审批，Bot 生成 Ticket 就直接下单、付款、删数据，等于把钱和数据交给了模型。模型读到的工具参数里可能夹带提示注入，不能让它决定是否放行花钱类动作。
- 要补上分层审批：只读直接做，花钱必须人点卡片，超预算直接拒，批了什么、谁批的、什么时候批的，都要落库。

## 改什么（范围）

只加审批，不改 Ticket 生成逻辑：

1. **先复用，再新建**：OpenMausBot 已有审批分级文档（`docs/approval-levels.md`）、权限代理（`server/permission-proxy.ts`）、自动审批（`auto-approve.ts`、`always-allow.ts`）、决策日志（`decision-log.ts`）、预算计数（`spend.ts`、`harness-budget.ts`）和密钥存储（`cloud-secrets.ts`，以及 README 里的 Vault 密钥卡）。本 change 先对照这些模块，列出“已有 / 要改 / 要新建”，再写 tasks。
2. **分层审批，四层**：1 直接做：只读；2 智能审批：一般写操作，先让评审模型看；3 先问人：花钱 / 下单 / 付款 / 删数据 / 对外发消息，必须弹卡片；4 交回给人：超预算 / 不在白名单 / 评审判有风险。
3. **硬规则在前，模型评审在后**：分层顺序固定为“代码规则（白名单、预算、动作类型）→ 评审模型 → 人”。评审模型**只能把风险往上调，不能往下调**；超时、报错或输出无法解析时一律按“先问人”处理（失败即拒绝）。
4. **审批卡片**：Allow once / Always allow / Deny，卡片上写清楚做什么、花多少钱、给谁、有什么风险。飞书交互卡片要单独接入回调权限（MVP1 没开卡片回调），校验点击人的 `open_id` 必须是这张 Ticket 的批准人，同一张卡片重复点击要幂等，卡片过期后点击无效。
5. **凭据 vault**：真实凭据放 vault，Agent 只拿临时替身 token，用完失效；每个客户 vault 分开。Composio 的 OAuth 连接已经由代理持有凭据，可以直接复用。
6. **预算上限**：单笔 / 日 / 月上限，超了直接停，不问模型。区分“模型 token 花费”和“业务花费（下单金额）”，两者分别设上限。现有 `spend.ts` 只管前者。
7. **审计记录**：谁批的、批了什么、什么时候批的、花了多少钱，落库，能查到。

## 不动什么（边界）

- 不改 Ticket 生成逻辑：Ticket 字段、Mandate 不可变、去重、observe，那是 MVP2a 已完成的事。本 change 只在 Ticket 上加审批。
- **不做完整的凭据代理**：自建业务系统的凭据，通过控制面的出口代理在请求时注入，agent 进程里始终没有真实凭据。这一项工作量大，拆成单独的 change `add-credential-proxy`，本 change 只做到：Composio 复用 + Vault 分开 + 临时替身 token 的接口，具体注入逻辑在下一个 change 里做。
- 不做路由 / Jev 分流：那是 MVP3 的事。
- 不做只读巡检：那是 MVP4 的事。
- 不做记忆与技能：那是 MVP5 的事。
- 不改 OpenMausBot 核心的 bot 调度、记忆、harness 服务；不删模块。
- 不接钉钉 / 企业微信；先只做飞书。

## 验收标准

- [ ] “查一下库存”，不弹卡片，直接回。
- [ ] “帮我下单买 10 件”，弹卡片，点了才下，不点不下。
- [ ] 超预算的单，直接拒绝，有日志。
- [ ] 评审模型超时，降级为弹卡片，不会直接执行。

- [ ] 同一张卡片点两次，只执行一次。
- [ ] Agent 看不到真实凭据，只能拿到临时替身 token。
- [ ] 审批记录能查到：谁批的、批了什么、什么时候批的、花了多少钱。

## 风险

- 评审模型被提示注入，判花钱的动作为低风险。防法：硬规则在前，评审模型只能往上调，不能往下调；花钱类动作不能由评审模型放行，必须弹卡片。
- 评审模型超时，Bot 直接执行。防法：超时、报错或输出无法解析时一律按“先问人”处理。
- 群里其他人代点卡片。防法：校验点击人的 `open_id` 必须是批准人，非批准人点击无效并有日志。
- 同一张卡片点两次，执行两次。防法：幂等，第一次点击后状态已变，第二次点击无效。
- 卡片过期后还能点。防法：卡片过期后点击无效。
- 隔离环境验证：凡是涉及写入的验证，只能在隔离测试环境中做，不能用正在运行的应用或真实数据。
