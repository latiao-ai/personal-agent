## 为什么改

- 现在 OpenMausBot 没有飞书入口，客户只能在网页 / App 里说话；飞书是电商 Bot 的前台。
- 先跑通最小闭环：飞书私聊发一句话 → 网关收到 → 固定 Bot 回一句话。通了，再往上加群聊、工单、审批。

## 改什么（范围）

只加一个飞书网关适配器，不动核心 bot 逻辑：

1. 飞书网关：WebSocket 长连接模式，**不用公网地址**（学 Hermes 的做法）。
2. 私聊收发：飞书私聊发一句话，Bot 能收到并回一句话。
3. 白名单鉴权：只有白名单里的人能进，陌生人直接拒绝，不回、不生成 Ticket。
4. 断线重连：WebSocket 断了能自己连回来，不用手动重启；重启后已收到的消息不重复回。

## 不动什么（边界）

- 不做群聊（群里 @、群消息）：那是 MVP3 路由的事。
- 不做工单 / Ticket / Mandate：那是 MVP2 的事。
- 不做审批卡片（批准 / 拒绝回调）：那是 MVP2 的事。
- 不做日报推送：那是 MVP4 只读巡检的事。
- 不做文件收发、不做自动采购。
- 不动 OpenMausBot 核心的 bot 调度、记忆、harness 服务；不做 Jev 分流，不做模型选择——
  MVP1 只转给一个固定 Bot。
- 不接钉钉 / 企业微信；先只做飞书。

## 验收标准

- [ ] 飞书私聊发“你好”，5 秒内 Bot 能收到。
- [ ] Bot 回一句话，飞书私聊上能看到。
- [ ] 白名单外的人发消息，网关拒绝，不回、不生成 Ticket，日志里有拒绝记录。
- [ ] 飞书私聊发 3 句话，Bot 都回了。
- [ ] 网关重启，之前已收到的消息不重复回。
- [ ] 断线重连：WebSocket 断了能自己连回来，不用手动重启。
- [ ] 全程不要求公网地址 / 域名。
- [ ] `openspec validate --all --strict --no-interactive` 通过；`tasks.md` 全勾完；`handoff.md` 写清楚。

## 风险

- 飞书应用的权限要在飞书开放平台先建应用、配好权限（私聊消息接收），这一步在飞书侧做，不在代码里。
- App ID / App Secret 只放本地配置或环境变量，不进仓库、不进 change 文件。
- 本地源码结构以 Mac 上实测为准：动手前先做第 0 步（原样跑通、画结构图），标出网关接入点再写代码。
